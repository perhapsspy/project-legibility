# Critical Review

원래 문제를 해결하는지, 빠진 것이 무엇인지, 불필요한 부담이 무엇인지 판단한다. 검토를 새 요구를 만들거나 지적을 억지로 채우는 기회로 삼지 않는다.

## 판단 기준을 복원한다

원 요청, 최신 교정·확정 결정, 정본과 실제 산출물을 대조한다. 목적·범위·지원 조건·관찰 가능한 완료 모습을 잡는다. 확인한 맥락을 재사용하며, 제안이나 이전 리뷰 지적을 요구로 승격하지 않는다. 판정을 바꿀 정보만 보충한다. 필요한 결정이 없으면 의존하는 일만 멈춘다.

## 영향을 받는 사용 흐름을 읽는다

변경 조각을 넘어 사용자·소비자의 의도부터 결과까지 판단에 필요한 경로를 연결한다.

- 코드는 결과에 영향을 주는 계약·상태·단위·이름·경계에서 호출부와 구현을 연결한다. 소비자가 장황한 예시나 내부 지식을 알아야 한다면 문서를 더 권하기 전에 인터페이스와 책임을 살핀다. 화면의 증상도 필요하면 데이터 계약까지 추적한다.
- 기획·설계는 무엇을 왜 만드는지 실제 사용자 흐름, 책임, 변경 대상과 연결한다. 다음 작업자가 이전 대화를 몰라도 실행할 수 있어야 한다. UI는 기존 디자인의 정보 위계·배치·조작 흐름을 살핀다. 시각적 주장이 달려 있다면 최종 렌더링을 직접 확인하며, 설명 문구 추가로 흐름의 결함을 덮지 않는다.

판단에 맞게 깊이를 조절한다. 구체적인 구조·정본·문서 문제가 전문 지침을 요구할 때 연결하되 전체 절차를 중복하지 않는다.

## 지적 자체도 반증한다

자신의 제안과 각 후보 지적을 반증할 반례·다른 원인·더 단순하고 충분한 대안을 찾는다. 충분한지와 과한지를 모두 묻는다. 적합한 공용 구현을 재사용하되 승인된 목적이 요구하면 더 큰 변경도 허용한다. 기존 설계나 작은 diff 자체를 정답으로 삼지 않는다.

절차·endpoint·스크립트·추상화·보호 로직·문서 제안은 현재 요구나 지원 조건의 실제 실패와 연결한다. 소비자 부담과 중복 정보의 유지 비용도 포함한다. 근거가 성립하지 않는 권고는 제거한다. 현재 근거가 뒷받침하는 권한·안전·복구 경계를 보존한다. 결함, 선택적 개선, 미결정을 구별한다.

## 결론을 바꿀 증거를 얻는다

가장 작은 관련 실험·계측·렌더링 확인을 고른다. 실험 전 실제 외부 연결과 부작용을 확인하며 환경 이름으로 안전을 추정하지 않는다. 성능은 같은 환경·입력·작업량으로 비교한다. 현재 revision과 범위에 유효한 검증은 재사용하되 해석은 독립적으로 판단한다. 중복 검사나 주장한 계약을 증명하지 못하는 테스트를 늘리지 않는다.

소스 사실·실행 관찰·추론·미확인을 나눈다. 결함 재현과 운영 사건의 원인 확정을 구별한다. 등록·예약·쓰기·검사 성공을 사용자 결과나 전체 요구 충족으로 바꾸지 않는다. 독립 검토를 요청받았다면 원 요청과 최소 원자료·검증 증거를 전달하고 작성자의 결론으로 유도하지 않는다. 요청된 방식은 지키되 모델·역할 체계·고정 병렬 수를 상시 의무로 만들지 않는다.

## 승인 범위에서 끝낸다

리뷰만 요청받았으면 진단으로 끝낸다. 수정까지 승인됐다면 범위 안에서 고치고 영향을 받은 동작을 재검증한다. 리뷰 완료가 남은 승인 작업을 취소하지 않는다. 새로운 목적·범위·권한이 필요한 변경만 결정받고 독립 작업은 계속한다. 리뷰는 게시·설치·배포를 승인하지 않는다.

## 간결하게 판정한다

중요한 문제부터 영향·직접 근거·필요한 최소 변경·확인 방법을 연결한다. 보고 전에 각 지적을 원 기준과 반대 근거에 대조한다. 실제 문제·제안·미확인을 구별한다. 유의미한 문제가 없으면 확인 범위와 남은 한계와 함께 그렇게 말한다. 답변만으로 판단할 수 있게 쓰며, 요청하지 않은 장문 보고서나 추적 문서를 늘리지 않는다.
