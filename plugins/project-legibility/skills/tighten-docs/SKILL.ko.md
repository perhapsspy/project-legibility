# Tighten Docs

## 목적과 우선순위

선택된 문서, diff, 문서 패키지를 하나의 분명한 현재 최종 상태로 만든다. 사람이 작성하는 문서에는 첫 문장부터 최종 리뷰까지 이 스킬을 기본 품질 패스로 사용한다. 원문의 의미를 바꾸지 않고 문장을 다듬으며 문서 역할, 독자 경로, 현재 소유권을 명확히 한다.

사용자와 저장소 지침, 선택된 문서 형식의 전용 계약, 확인된 기준 근거, 이 일반 규칙 순으로 적용한다. 미확정 상태를 보존한다. 적용되는 근거가 필요한 정책이나 소유권 선택을 정하지 않았다면 직접 결정하지 말고 짧게 확인하거나 결정 요청으로 남긴다.

## 범위와 권한

대상 표면은 문서 하나 또는 명시적으로 선택된 패키지로, 권한은 리뷰 또는 편집/정리로 정한다. 코드·제품·운영 작업에 딸린 산출물이어도 사람이 읽는 본문을 작성·수정·리뷰하라는 요청이 있으면 그 문서 표면이 선택된 것이다. 별도 정리 요청이나 대규모 개정을 기다리지 않는다. 사람이 작성한 문장과 구조를 건드리지 않을 때만 기계적 수정으로 본다. 리뷰는 읽기 전용이다. 편집이나 정리는 선택된 문서 범위만 바꿀 권한이다. 문서 생성, 이동, 삭제는 사용자가 변경을 요청했고 적용되는 계약이나 근거가 그 동작을 정당화할 때만 수행한다.

작업 전에 각 대상의 역할, 핵심 주체, 독자 행동, 문서가 책임지는 약속, 함께 바뀌는 일관된 단위를 확인한다. 요구 본문 언어와 로캘을 따른다. 코드 식별자, API 이름, 파일 경로, 명령어, 제품명, 도메인 용어, 인용된 프로토콜 문구, 외부 소유 라벨은 그대로 둔다.

## 최종 상태 규칙

- 최신 지적이나 작성 제약을 직접적인 최종 문장으로 반영한다. 대상이 그 목적을 맡지 않는 한 거절·노후·제외·중복된 내용, 방어적 설명, 작업 과정과 편집 메타 설명을 삭제한다.
- 사실, 약속, 담당, 날짜, 제약, 결정, 구현 의미를 보존한다. 레거시, 대체 경로, 예외, 경고, 라우팅 주장은 선택된 근거가 현재 필요성을 증명할 때만 남긴다. 국소 교정은 사용자가 더 넓은 정책을 요청하지 않는 한 국소적으로 유지한다.
- 대상이 무엇을 하고, 제공하고, 요구하는지 긍정형으로 직접 쓴다. 부정이나 대비는 실제 금지, 한계, 안전 경계, 호환 조건, 명시적 비교에만 쓴다.
- 공개 진입점은 확인된 독자 상황, 결과, 다음 행동을 먼저 제시한다. 내부 메커니즘은 그 판단에 도움이 될 때만 남긴다.
- 유지할 일반 문장은 요구 언어로 고치고, 다른 언어의 여분이거나 오래된 문장은 삭제한다. 적용되는 언어 또는 로캘 요구가 충돌하면 확인한다.
- 구조 변경이 독자 행동, 소유권, 운영 사용성을 실질적으로 개선하지 않으면 변경하지 않거나 가볍게만 고친다.

## 제거 규율

- 거절·제거·교체된 판단은 현재 정본에 존재하지 않는 것으로 다룬다. 지원하지 않음, 사용하지 않음, 더는 계획하지 않음, 의도적으로 제외함 같은 부정문으로 그 의미 흔적을 보존하지 않는다.
- 선택된 현재 정본 범위에서 제거된 판단의 이름, 별칭, 바꿔 쓴 표현과 그 판단에 딸린 근거를 찾는다. 그 판단을 기억하거나 반박하는 일만 하는 비교, 부정, 경고, 예외, fallback 문구, 경로 흔적, 설명을 삭제한다. 대상이 역사, 결정 근거, 안전, 호환성 증거를 명시적으로 소유할 때만 남긴다.
- 반사실 검사를 사용한다. 폐기된 선택지가 처음부터 제안되지 않았어도 현재 독자가 올바르고 안전하게 행동하려면 이 문장이 필요한가? 아니면 삭제한다. 필요하다면 남은 현재 규칙, 요구사항, 독자 행동을 직접 쓰고, 경계 자체가 현재 유효하며 근거로 확인될 때만 부정문을 유지한다.
- 리뷰에서는 이 검사를 통과하지 못한 흔적을 문장 개선안이 아니라 삭제 이슈로 분류한다. 편집에서는 보고만 하고 남겨두지 말고 선택된 범위 전체에서 제거한다.

## 패키지 소유권

문서 역할은 고정 템플릿이 아니라 판단 기준이다. **진입점**은 목적·현재 상태·시작점을, **라우터**는 독자 작업과 소유 문서의 연결을, **현재 소유 문서**는 현재 주제·계약·결정·게이트·계획 하나를 맡는다. **게이트/런북**은 운영 사전 조건과 안전 경계를 맡고, **백로그**는 실시간·삭제형·역사형 중 성격을 밝힌다. **증거/로그**와 **작업/보관 문서**는 증명·시간 순서·미확정·오래된 자료를 현재 정본과 구분한다.

현재 정본을 증거, 시간 순서, 초안, 보관 자료와 분리한다. 현재 결정, 계약, 게이트, 계획마다 소유 문서 하나를 둔다. 문서 소유권은 정본 주장과 독자 경로를 다루며, 선택된 근거가 해당 런타임 계약을 소유하지 않는 한 런타임 UX 구성, 정보 계층, 컴포넌트 재사용을 규정하지 않는다.

부분이 독립적으로 유용한 독자 행동, 소유권, 변경 이유를 가질 때만 문서를 나눈다. 독자가 함께 사용하거나 하나의 일관된 계약·절차를 완성하는 내용은 함께 둔다. 길이, 제목 수, 개념 이름만으로 나누지 않는다.

일반적인 링크와 동시 수정은 결함이 아니다. 경쟁하는 정본 정의, 결정, 계약, 절차를 없앤다. 소유권이 이동하면 이전 문서를 새 소유 문서로 연결하거나 역사/보관 상태로 표시한다. 라우터는 대상 독자, 선택 기준, 순서, 전제조건을 소유할 수 있지만 다른 문서의 정본을 복제하지 않는다.

이메일, 체크리스트, ADR, 런북, 인수인계, 로그처럼 유용한 원문 형식을 보존한다. 역사 정리를 명시적으로 요청하지 않았다면 append-only 기록을 정리 편의로 다시 쓰지 않는다.

운영 게이트와 런북은 필요한 사전 조건, 허용 동작, 중단 조건, 승인 경계, 증거, 롤백, 복구가 있고 실제로 사용 가능한지 확인한다. 확정된 근거의 의미는 보존하고, 빠진 운영 결정은 만들지 말고 보고한다.

## 출력과 이관

승인된 편집은 가능하면 선택된 파일을 직접 바꾸고, 실질적인 소유권·경로 변경과 막힌 결정을 보고한다. 리뷰는 심각도 순으로 문제와 위험부터 제시하고, 근거를 필요한 변경이나 결정 요청에 연결한다. 인계 전에는 폐기된 선택지가 처음부터 없었다고 가정하고 바뀐 현재 정본 문장을 다시 읽는다. 반사실 검사를 통과하지 못한 흔적을 없애고, 남은 부정문마다 현재 독자 행동, 안전, 호환성 필요가 있는지 확인한다. 응답은 작업에 비례하게 유지하며 요청받지 않은 별도 리뷰 보고서, 작업 문서, 문서 표면을 만들지 않는다.

외부 기준 소스 선택, 제품·정책·아키텍처·구현 결정 생성, 작업 상태·작업 로그·인수인계 저장 구조 설계, 구현 계획의 의미나 범위 변경, 순수 번역·지역화, always-read 저장소 지침 파일의 의미나 구조 결정이 필요하면 멈추고 확인하거나 이관한다. 이미 확정된 지침이나 계획의 문장 다듬기는 허용된다.
