# 목적에 맞는 설계

## 역할과 종료

사용자·도메인 목적, 명시 제약, 현재 근거, 관찰 가능한 최소 성공 조건에서 초기 방향을 정한다. 기존 구현, 선례, 기본값은 자동 기준이 아니라 근거로 다룬다.

잠정 방향, 가장 작은 유용한 확인, 또는 선택을 막는 질문 하나로 끝낸다. 작은 선택은 한 문단이면 충분하며 탐색 중 구현 범위를 넓히지 않는다.

## 결정 계약

- 원하는 결과와 관찰 가능한 최소 성공을 밝힌다.
- 명시된 한계를 보존한다. 사용자 정정과 제외한 개념은 요청이 미치는 범위에서 구속력 있게 다루고, 다른 이름이나 계층으로 다시 들이지 않는다.
- 기존 코드나 선례에서 확인된 근거, 모르는 것, 단지 암시된 것을 구분한다. 긴급함은 전달 제약이지 방향이 적합하다는 근거가 아니다.
- 잠정 방향과 이를 바꿀 근거 또는 가장 작은 확인을 제시한다. 빠진 사실이 선택을 바꿀 때만 조사하거나 질문 하나를 하고, 그렇지 않으면 불확실성을 밝힌 채 진행한다.
- 책임, 영속 상태, 정책, 의존성, 생명주기, 공개 계약, 호환성, 되돌리기 어려운 결합이 실질적으로 달라질 때만 대안을 비교한다.

기술적 기본값, 대체 처리, 보안·일관성 주장도 사용자에게 보이는 동작, 도메인 의미, 정책을 바꾸면 설계 선택이다. 그렇지 않으면 구현 세부사항으로 둔다.

임시 작업은 목적과 제약을 지키는 가장 작은 유용한 범위로 고른다. 검증하고 되돌릴 현실적인 방법을 두며, 실질적으로 도움이 될 때만 어댑터, 래퍼, 롤백 경계를 추가한다.

## 경계와 이관

남은 문제가 분명하면 이를 소유한 workflow로 넘긴다.

- 따라야 할 계약을 모르면 기준 소스를 확인한다.
- 사용자 의도, 비동기 작업, 표현, 최신성이 얽히면 상호작용 상태 흐름을 다룬다.
- 방향이 정해지고 여러 표현에 걸친 확정 의미의 소유권, 코드 형태나 검증이 남으면 구조 작업으로 넘긴다.

방향이 이미 정해졌다면 여기서 다시 설계하거나 코드·상태·소유 구조를 결정하지 말고 확정된 계약을 관련 workflow에 넘긴다. 전문 결정을 이 스킬 안에서 수행하지 않는다. 목적, 제약, 근거, 성공 조건, 남은 사실을 넘겨 새 근거 없이 제품 방향을 다시 열지 않게 한다.
