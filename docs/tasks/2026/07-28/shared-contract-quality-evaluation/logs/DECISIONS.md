# Decisions

**2026-07-28**

- **Background:** 공유 계약, 품질 결합도, 리뷰 증거, 완료 기준과 반복 기준선 보강 후보를 그대로 추가하면 기존 계약 중복과 과잉 절차가 생길 수 있었다.
- **Decision:** 공유 해석의 단일 정본, 관찰과 원인 가설의 분리, 완료 관문과 지향 비교 목표 구분을 핵심으로 채택하고, 병렬화·baseline·Director Charter 규칙은 기존 문장에 한정형으로 합친다.
- **Why:** 딥 리즈너 검토에서 이 구성이 실제 행동 차이를 만들면서 문서 자동 생성, review soup, 종료 불가능 반복과 정본 복제를 함께 억제하는 최소안으로 확인됐다.
- **Impact:** 정본 여섯 파일은 긍정형 소유·판정 문장으로 바뀌고, Project Legibility 생성 snapshot과 release는 사용자 리뷰 뒤 정본 commit·push를 기준으로 갱신한다.
