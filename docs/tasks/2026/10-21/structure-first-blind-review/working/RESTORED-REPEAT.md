# 문장 복원과 singleflight 반복 비교

2026-10-21, 승인한 원복을 적용하고 같은 singleflight 사례를 새 worker 한 쌍으로 반복 비교했다. **복원 전·후 모두 같은 결함을 발견·직접 재현했다. 이번 반복에서도 마지막 문장 교체의 추가 발견 효과는 관측되지 않았다.**

## 반영과 평가 정정

정본 `structure-first`에서 `4ecfc9f7e9f2025d9693862307da79fec1fd87a9`가 교체한 Verification 영·한 한 문장만 복원했다. 복원 commit은 `9b21db1efe765c3ccf08c75f5627c4c8f8850309`이며 정본 main push 후 원격 SHA를 확인했다. 스킬 파일 전체는 `5be8eaf`의 내용과 같다. 원천 근거·보존 지식 추적 개선, Runtime Contract와 Structural Boundaries는 유지했다.

정본 유효성 검사 후 기존 동기화 절차로 로컬 생성 bundle·lock·notices를 맞췄다. offline 검사·bundle 검증·저장소 unittest 57개가 통과했다. 미릴리스 변경이며 plugin version·tag·publisher pin·설치 cache는 변경하지 않았다.

A2는 전체 외부 이력의 도달성이 미검증인 조건부 합성 반례로서 지원 결함 평가에서 제외했다. A2 미보고에 따른 coverage·교정 수용 실패 판정은 철회했고, 기존 세 실행 보고의 안내에도 명시했다. 당시 실행 관측과 채점 기록, A1 및 다른 유효한 결함의 결과는 보존했다. 판단 근거는 [평가 정정과 적용 범위](FOLLOWUP-PROPOSAL.md)가 소유한다.

## 고정 조건

[직전 비교](TRANSFER-COMPARISON.md)의 동일 사례·계약을 재사용했다. 소스는 `golang/sync@e225da77a7e68af35c70ccbf71af2b83e6acac3c`의 원문 `singleflight.go`이며 SHA-256은 `8853de5a62b9ee4550dbbe1034bf935ea4819d79d70c33b0af0a743e4089261d`다. 원본 LICENSE, Go 1.25.0 module wrapper와 API 주석을 옮긴 계약도 유지했다. 계약 SHA-256은 `4e77da6a0472132d26716139a59c972c27e86993463b6b25612e587f57fce53b`다. 실제 toolchain은 Go 1.27.2 darwin/arm64였다.

양쪽 입력은 각각 소스·계약 4개와 스킬 7개, 총 11개 파일이다. 영·한 Verification 문장이 있는 두 파일만 달랐다. 버전을 중립 case에 무작위 배치하고 입력 해시와 평가 기준을 먼저 고정했다. 이번 요청문은 같은 검토 범위로 작성했으며 양쪽에서 자기 경로만 달랐다. 직전 요청문과 바이트 단위로 동일하다는 검증은 하지 않았고, 직전 점수와 합산하지 않는다.

새 `worker` 두 명은 모두 `gpt-6.1-sol/high`, `fork_turns=none`으로 시작했다. 각 8분·exec 명령 25회 이내의 한 번으로 제한했다. 전체 API 계약은 처음부터 제공했고, 결함 존재·개수·위치·실패 이력·정답·이전 결과는 제공하지 않았다. 추가 계약 조항 지정이나 답을 보완하는 후속 지시는 없었다. 따라서 이번 점수는 제공 계약에 대한 첫 검토 결과이며 별도의 계약 지정 후 점수는 없다.

평가 표적과 공개 API 도달성의 근거는 직전의 공식 수정 전후 witness 검증을 재사용했다. 이번에는 worker의 재현이 원문 구현과 실제 공개 API를 사용하는지 직접 확인했다. 두 보고서와 테스트·로그 해시를 고정하고 입력 보존을 확인한 뒤 배정을 열었다. 결과에 따라 재위임하거나 사례·채점 기준을 바꾸지 않았다.

## 결과

양쪽 모두 A 실행 → Forget → B 실행 → A 완료 → B 진행 중 C 호출의 이력을 만들었다. A의 완료가 B의 등록을 삭제해 C가 B의 결과를 공유하지 않고 별도 실행되는 것을 확인했다. Forget이 허용한 A/B 중첩 자체를 결함으로 오인하지 않았다. 복원 전은 A/B 진입 API 네 조합, 복원 후는 A=DoChan과 B 진입 API 두 조합을 재현했다. 조합 수 차이는 별도 결함 발견 점수가 아니다.

두 테스트 모두 외부 test package에서 공개 API만 사용했다. 내부 Group 상태를 주입하거나 원문 구현을 바꾸지 않았다. A 결과 수신으로 A의 정리가 끝났음을 확인하고, B를 막은 채 C의 DoChan 호출을 완료해 필요한 순서를 보장했다. 정상 대조는 일반 중복 합류와 완료 후 새 실행을 포함했다. 복원 후 worker는 A가 남아 있는 동안 Forget 이후 B가 독립 실행되는 정상 사례도 따로 확인했다.

메인이 양쪽 구현·go.mod 복사본의 동일성을 확인하고 `go test -race ./singleflight -v -count=1`로 재실행했다. 위 재현 subcase는 기대한 잘못된 결과·shared 값과 별도 실행 때문에 실패했고 정상 대조는 통과했다. compile 실패·timeout·race 경고로 인한 실패가 아니었다. 관측한 실행에서 race 경고가 없었다는 범위만 확인했다.

세션은 복원 전 `01a15d8c-2858-7243-be56-16430d912d95`, 복원 후 `01a15d8b-f8e9-7f82-b91b-4aae3fba2e83`다. 실행 기록에서 모델·effort·예산·지정 스킬 참조·Go 지침 적용을 확인했다. 기록된 명령에는 다른 case·평가자·메모리·세션·upstream 접근 신호가 없었다. 이는 지시·실행 기록·파일 해시 검사이며 OS 접근 격리는 아니다.

## 해석과 종료

이번 반복에서 복원본도 기대한 추적 행동과 같은 표적 발견을 수행했다. 앞선 마지막 문장 교체를 다시 유지할 추가 근거는 얻지 못했다. 시간·명령 수 차이를 성능 이득으로 해석하지 않는다.

새 worker를 사용했지만 사례는 직전과 같은 공개 사례다. 모델의 사전 친숙도는 통제하지 못했고 새로운 독립 사례가 늘어난 것이 아니다. 이 한 쌍으로 일반 발견률, 문구의 동등성·인과 효과, 원래 제품의 모든 결함 발견을 주장하지 않는다. 승인한 반복 한 쌍에서 종료하며 검토한 임시 입력·테스트·원시 출력은 정리했다. 실행 근거는 해당 worker와 메인 Codex 세션에 보존한다.
