## 발견과 누락

| 기존 결함 | 블라인드 판정 | 직접 근거 |
|---|---|---|
| 과거 NTP 패킷을 새 수신으로 오인 | 누락 | 최종 리뷰에 해당 조건·결함이 없었다. 메인이 별도 overlay로 최초 이력 부재와 ignored 뒤 정보 소실 두 조건을 역검증하자 실제 새 수신 없이 모두 `mode=ntp`, `reason=ntp_restored`가 발생했다. |
| 수동 run의 전체 구간 안전조건 우회 | 발견·직접 재현 | 에이전트가 직접 작성한 `TestReviewManualRunIntervalSafety`에서 `6초 ±2초`, `24시간−1초 ±2초` 각각 수동 clock 호출 1회·success, 자동 clock 호출 0회를 확인했다. 메인 재실행도 같았다. |
| management 실패가 status의 owner 오류·재시도를 숨김 | 누락 | 최종 리뷰에 해당 조건·결함이 없었다. 메인의 별도 역검증에서 깨진 management JSON과 유효한 owner 오류 record를 주자 `err=nil`, `status=ok`, `Health=nil`이 나왔다. |

에이전트는 별도로 저장된 `ControlUnconfirmed=true`를 수동 run이 무시하고 clock을 설정하는 경로도 재현했다. 원래 세 결함의 발견 점수에는 포함하지 않았다. 실패한 clock worker가 기존 관측을 덮어쓴다는 다른 가설은 테스트로 배제했다. 추가 finding은 현재 제품 구현의 결함으로 확장하지 않았다.

에이전트가 작성한 세 특성 테스트를 메인이 `-count=1`로 재실행해 동일한 결과를 얻었다. 이 테스트의 통과는 결함 관측이 재현됐다는 뜻이다. 메인 역검증 세 테스트는 계약 위반 때문에 예상대로 실패했다. 실제 clock·systemd·외부 HTTP 효과는 fixture로 차단했다. 메인 역검증은 블라인드 응답 완료 뒤 시행했으며 에이전트에게 전달하지 않았다.

## 판단의 한계

이 1회에서는 수정된 스킬을 읽고도 두 결함을 놓쳤다. 세 결함을 모두 찾아내는 실효성은 입증되지 않았다. 구버전 대조 실행·반복 표본이 없고 원본 테스트도 제외했으므로 개선 전후의 인과효과·재현율은 판정할 수 없다. 이 결과는 해당 소스 전용 fixture의 독립 리뷰 결과이며 전체 과거 환경이나 현재 제품의 수용 판정이 아니다.
