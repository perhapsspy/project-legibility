# 생성 근거 검증 개선 후 NTP 지정 진단

**평가 정정(2026-10-21):** A2는 전체 외부 입력 이력의 도달성이 미검증이므로 지원 결함 평가에서 제외한다. A2 미보고에 따른 스킬 coverage·교정 수용 실패 판정은 철회한다. 아래 실행 관측과 당시 합성 기준의 채점 기록, A1 및 다른 유효한 결함의 결과는 보존한다. [현재 평가와 적용 범위](FOLLOWUP-PROPOSAL.md)를 따른다.

2026-10-21, 개선 스킬을 읽은 새 worker 한 명이 **최초 기준값이 없는 NTP 오복귀를 발견·재현했다. ignored snapshot 뒤 수신 이력이 가려지는 조건은 보고하지 않았다.** 원천 사건을 고정하고 관측 이력을 바꾸는 검증 행동은 나타났지만, 사전에 고정한 두 실패 이력 전체의 발견 기준은 충족하지 못했다.


## 변경과 실험 조건

Pro 제안에 따라 Structure First의 영·한 Verification 첫 문단을 교체했다. 파생 판단의 대입·실행 조건을 원천 사실까지 거슬러 추적하고, 관련 단위가 보존하는 정보와 비교의 선행 근거를 확인하며, 원천 사건을 고정한 채 관측 이력을 바꾸도록 했다. 정본 commit은 `5be8eafbb18747a19dcd3efc7927abbd5c0ed605`다.

실험은 새 `worker`, `gpt-6.1-sol/high`, `fork_turns=none` 한 명으로 수행했다. 상한은 8분·실행 명령 25회였고, 실제 기록은 약 223초·명령 9회였다. 세션 ID는 `01a15c90-0375-7d03-8d6c-08be1d30e7b4`다.

원문 계약, 복원 소스, 개선 스킬을 제공하고 다음 원문 조항만 지정했다.

> 회복 확인 구간에서 새로 받은 정상 NTP 응답이 있고 NTP가 active다.

정답·결함 개수·의심 위치·실패 이력·이전 판정은 제공하지 않았다. 평가 기준은 위임 전에 고정했다. 종료 후 답을 주거나 후속 worker를 추가하지 않았다. 이전 [구·신 비교](COMPARISON.md)의 두 조항 지정 단계보다 범위를 좁힌 진단이며, 무힌트 실험 점수와 합산하지 않는다.

## 판정

| 평가 항목 | 결과 | 직접 근거 |
|---|---|---|
| 원천에서 최종 판단까지 추적 | 수행 확인 | 실제 `ReadTimeHealthNTP → observeNTP → timehealth.Evaluate`를 연결하고, 수신 ID·관측 시각·baseline·복귀 조건의 생성 경로를 설명했다. |
| 원천 사건 고정, 관측 이력 변경 | 수행 확인 | 같은 과거 패킷을 유지한 채 최초 D-Bus 조회 성공 여부만 바꾸어 복귀 여부 차이를 실행했다. |
| A1: 최초 기준값 부재 | 발견·직접 재현 | 최초 메타데이터 조회 실패 뒤 과거 패킷이 처음 보이자 `fresh=true`, 이후 `ntp_restored`가 됐다. |
| A2: ignored snapshot 뒤 이력 소실 | 미보고 | runtime에는 수신 이력이 남고 policy의 현재 snapshot에서만 가려지는 이력을 구성하거나 지적하지 않았다. |
| 대조 사례 | 실행 확인 | 처음부터 보이던 같은 패킷만으로는 복귀하지 않았고, 실제 새 패킷과 정상 시간 확인이 있는 경우 복귀했다. |

A1에서 고정한 패킷 A는 회복 전 수신한 count=7이며 transmit·destination 값도 그대로였다. t=10초의 메타데이터 조회가 실패하고 t=310·610초에는 성공했다. 최초 성공 관측을 새 수신으로 간주하면서, 새 수신 없이 NTP 모드로 복귀했다. 최초 조회가 성공한 대조에서는 같은 A만으로 fallback을 유지했다. 정상 대조에서는 회복 중 count=8인 B를 공급해 복귀했다.

worker가 작성한 `TestReviewNTPRecoveryVisibility`의 세 subtest를 메인이 `-count=1`로 다시 실행해 같은 결과를 확인했다. 세 테스트의 PASS는 첫 사례에서 **기존 오동작이 재현됐음**을 포함한다. 제품 계약이 모두 충족됐다는 뜻은 아니다.

A2는 이미 보유한 accepted ID와 policy baseline 사이의 이력이 ignored 관측·메타데이터 실패를 거치며 어긋나는 조건이다. worker의 “같은 과거 패킷이 처음부터 보이는” 대조는 이 조건을 다루지 않는다. 따라서 이번 결과를 A2 발견으로 확장하지 않는다.

## 해석과 검증 범위

요청한 추적·반례 구성 행동이 실행됐으므로, 이번 누락을 단순한 지시 미이행으로 판정할 근거는 없다. 확인한 한계는 **그 행동을 수행하고도 다른 도달 가능한 보존 이력을 탐색하지 못했다는 것**이다. 인지적 원인은 이 한 번의 기록으로 확정할 수 없다.

앞선 실험에서는 못 찾은 NTP 결함의 한 이력을 이번에는 찾았지만, 계약을 더 좁혀 지정했고 한 번만 실행했다. 문구 변경만의 인과 효과나 일반적인 무힌트 발견력 향상을 입증하지는 않는다.

입력 103개 파일의 해시는 실행 전후 같았고, 제공한 스킬 7개 파일은 정본 commit의 archive와 일치했다. 소스·계약 96개 파일은 앞선 실험과 같은 복원 절차를 사용했다. 핵심 세 파일의 역사적 해시를 확인했고, 두 기존 NTP 반례가 모두 실패하는 상태를 위임 전에 확인했다. 전체 역사적 checkout은 아니며, 이후 snapshot에서 가져온 빌드 지원 파일과 원본 테스트 제거라는 [기존 복원 한계](RESULTS.md)를 유지한다.

실행 범위는 mock한 systemctl/busctl/networkctl 응답을 실제 parser·adapter·policy에 통과시킨 합성 경로다. resident 전체 루프, durable JSON 복원, 실제 D-Bus·systemd·HTTPS·현장 장비는 검증 범위 밖이다. 원시 출력과 실험 코드는 저장소 밖 임시 위치에서 검토 후 정리하고, 실행 근거는 해당 worker와 메인 세션 기록에 남긴다.

## 반영

정본 main에 commit을 push하고 원격 SHA를 확인했다. `sync_skills.py update --source structure-first=<commit>`으로 로컬 생성 스킬·source lock·notices를 동기화했다. 스킬 유효성 검사, bundle offline 검사, bundle 검증, 저장소 unittest 57개가 모두 통과했다. 이 변경은 미릴리스 상태이며 plugin version·tag·publisher pin·설치 cache를 변경하지 않았다.
